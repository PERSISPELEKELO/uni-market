# UniMarket AI Dispute Analysis Service

A small Flask microservice that analyses a dispute's text and returns a
sentiment score, a confidence score, a suggested resolution code, and a
plain-language summary. It exists to be called by the main Laravel
application (`app/Services/DisputeAnalysisService.php` in the repo root)
whenever a buyer raises a dispute - it is advisory only: if this service
is down, slow, or returns something malformed, Laravel still records the
dispute and leaves it for a human moderator. This service never makes a
final decision on any dispute by itself.

## How it works

- **Sentiment** comes from [VADER](https://github.com/cjhines/vaderSentiment)
  (`vaderSentiment` package), a lexicon- and rule-based sentiment model -
  not machine-learned - which is already scored on a -1 to +1 scale and
  fast enough to run per request with no training step of its own.
- **Category classification** (which drives the confidence score and the
  suggested resolution) is a real machine-learned model: TF-IDF features
  fed into a Logistic Regression classifier (`scikit-learn`), trained by
  `train.py` on `data/disputes.csv` and saved with `joblib`. It classifies
  dispute text into one of four categories: `misdescribed_item`,
  `delivery_issue`, `payment_issue`, `other`.
- Each category maps to a resolution code that Laravel stores verbatim:

  | Category | `suggested_resolution` |
  |---|---|
  | `misdescribed_item` | `PARTIAL_REFUND_OR_RETURN` |
  | `delivery_issue` | `REFUND` |
  | `payment_issue` | `PAYMENT_VERIFICATION` |
  | `other` | `MANUAL_REVIEW` |

- If the classifier's confidence for its top category is below
  `CONFIDENCE_THRESHOLD` (default `0.6`, override with an environment
  variable), the summary sentence gets an extra note: *"Low confidence,
  recommend careful human review."* There is no separate "escalate" field
  in the API response - Laravel already sends every dispute to a human
  moderator regardless, so this note is the practical way to flag it
  without needing a change on the Laravel side.
- The model and the sentiment analyser are both loaded **once**, when the
  process starts - not on every request - so a request is just inference,
  well inside Laravel's 3-second HTTP timeout. Each request's processing
  time is logged.

## The training data is synthetic

`data/disputes.csv` (220 rows, 55 per category) is **not real dispute
data** - it does not exist yet for this project. It's generated by
`data/generate_dataset.py`, which combines fixed phrase banks (an opening
sentence, a complaint detail, an optional closing line, all keyed by
category) with a fixed random seed, so the file is fully reproducible and
clearly templated rather than hand-written to look like more organic data
than it is. Re-running the generator produces byte-for-byte the same
`disputes.csv`. Describe it in your report as a synthetic, templated
dataset built for this project, not a real one.

## API

### `POST /api/analyze-dispute`

Request:
```json
{ "transaction_id": 123, "dispute_reason": "The seller never showed up for the handover." }
```

Response (`200`):
```json
{
  "sentiment_score": -0.51,
  "confidence_score": 0.87,
  "suggested_resolution": "REFUND",
  "summary": "Classified as a delivery issue (confidence 0.87). Buyer tone is negative. Suggested resolution: a refund."
}
```

`sentiment_score` is always clamped to `[-1, 1]` and `confidence_score` to
`[0, 1]` before it's returned, even though VADER and `predict_proba`
already guarantee those ranges in practice - the contract on the Laravel
side treats anything outside them as malformed and discards the *entire*
response, so this service never risks producing a value that would get
silently thrown away.

A request with a missing, empty, or non-string `dispute_reason`, or a
body that isn't valid JSON, gets a `400` with `{"error": "..."}` instead
of a crash.

### `GET /health`

Returns `{"status": "ok"}`. Useful for confirming the service is up
before raising a test dispute.

## Setup (Windows)

```bash
cd ai-service
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## Train the model

```bash
python train.py
```

This reads `data/disputes.csv`, trains the TF-IDF + Logistic Regression
pipeline, prints accuracy and a per-category precision/recall/F1 report
on a held-out 20% test split, saves a confusion matrix image to
`models/confusion_matrix.png`, and saves the trained pipeline to
`models/model.joblib`. A trained model is already committed in this repo
so `app.py` runs immediately after `pip install` without this step, but
re-run it any time `data/disputes.csv` changes.

To regenerate the training data itself (only needed if you change the
phrase banks):

```bash
python data\generate_dataset.py
```

## Run the service

```bash
python app.py
```

Runs on `127.0.0.1:8001` by default - deliberately not `8000`, since
that's also `php artisan serve`'s default port, and having both default
to the same address would mean the Laravel app calling itself instead of
this service. Override with the `PORT` environment variable if needed,
and update `AI_MODERATION_URL` in the Laravel app's `.env` to match.

## Run the tests

```bash
pytest
```

Tests stub out the model and the sentiment analyser (see
`tests/test_app.py`), so they run without needing `models/model.joblib`
to exist and without starting a real server - the same principle as the
Laravel side's own tests, which fake the HTTP call instead of hitting a
real service.
